# 申し送り（セッションの引き継ぎ）

止まっても後任がすぐ再開できるように、いまの状態を書き残す。トークンの上限は前触れなしに来るので、区切りごとに更新しておく。

リポジトリごとの値（持ち手の置き場所、作業の場所、一時の worktree、決まりの文書、本番、コンテキストの目安の見え方、申し送りの注意）は、値の表 `.claude/teamkit.md` にある（`python3 teamkit/values.py` で全部を出せる）。

## 置き場所と形

- 作業フォルダ直下の `TASK.md` の末尾に、申し送りの節を1つだけ置き、いつも**上書き**する（統括: リポジトリ直下の `TASK.md`、部: 値の表の「持ち手の置き場所」の `TASK.md`、ライン: `.worktrees/S<番号>/TASK.md`）。`TASK.md` は git に入らない。統括のほかの置き場所は TASK.md だけのフォルダで、git は作業の場所（値の表の「作業の場所」。直下でブランチを切るか、仕事ごとの一時の worktree）で使う
- 書くのは、コマンドで確かめた事実と、自分しか知らないこと（決めた理由、待っている相手、試して駄目だったこと）。60行くらいまで。秘密は書かない
- 値の表の「申し送りの注意」があれば、それも守る
- 時刻は日付と時刻で書く。「待っている返事」「動かしているもの」は、なければ「なし」と書く
- マージの許可は引き継がれない。取ったかどうかだけを書く

## いつ書くか

- コミット・push・PR・マージのあと: 「いまの状態」と「次にやること」の数行だけ直す
- 返事待ちに入る前: 「待っている返事」に足す。方針が変わったら「決まったこと」に足す
- `## タスク` の自分でやる行に取りかかるとき: `[ ]` を `[/]` にする（🔄 は道具がこの印から求める）。名前が20字を超える行なら、このとき短い名前と、その下の `- 説明: …`（何をして、どうなれば済みか）に分ける
- 依頼を受けて枝の行を足すとき: 名前は20字まで、その下に `- 説明: …`（任意。送り先への指示と経緯は書かない。書き方は `teamkit/templates/README.md`）
- 自分でやる行が済んだら: `[x]` と済んだ日 `（済: <月>/<日>）` を付ける。済んだ行はスプリントの終わりまで消さない（片付けは開発推進部。`teamkit/docs/taskmd.md` の4章）
- 束の行（子に任せた行）には印を書かない。束が進んだか済んだかは、道具が子の枝から求める（書き方は `teamkit/templates/README.md`）
- `/clear` の前、交代の前、上限が近いとき: 全部を見直す

## 区切りごとの /clear（すべてのセッション）

長く続くセッションほど、毎回の呼び出しで読み直す量が増える。統括・各部・ライン・部下のどれも、次のときに申し送りを書いて `/clear` し、TASK.md から再開する。

- 切るとき（どれか1つ）:
  - 人が**1時間以上**離れる見込み（外出、夜、長い待ち）。プロンプトのキャッシュは時間で切れ、戻ったときに会話の全部を読み直すことになるため
  - 部の依頼の区切り（【完了】を送って、次の依頼を待つとき）。ラインはマージして【完了】を送ったら閉じるので、切らずに止まる
  - コンテキストが値の表の「コンテキストの目安の見え方」を超えたあとの、最初の区切り
- 切らないとき: 人とやりとりが続いている（次の依頼がすぐ来そう）、1時間以内に戻る返事待ち（CI、短い確認）、コンテキストがまだ小さい（目安の半分くらいまで）。再開には TASK.md と決まりを読み直す分がかかり、小さいうちに切っても取り戻せない
- 手順: 申し送りを全部見直して書く（理由は「/clear の前」）→ 最後のメッセージで「/clear のあと、次を送ってください」と文で書き、再開文だけをコードブロックで出して止まる（`/clear` はコードブロックにしない。貼ると画面が消えて、再開文をコピーできなくなるため）。再開文はパス付き（統括は `TASK.md を読んで再開して`、ほかは `<作業フォルダ>/TASK.md を読んで再開して`）。人が続けて話しかけたら、切らずに続けてよい

## 書き残す

1. 状態を集める（読むだけ）: `bash .claude/skills/handover/state.sh <作業フォルダ>`（統括は `--all`）。作業の場所も `state.sh <作業の場所>` で（直下ならリポジトリ直下、一時の worktree ならその場所。置き場所は git の外なので、ブランチと PR は作業の場所の側で出る）
2. 下の型で書き、**`write.py` で書き換える**（申し送りの節だけを置き換え、ほかの見出しが変わるときは書かずに止まる）:
   ```
   python3 .claude/skills/handover/write.py TASK.md --from <新しい申し送りのファイル>   # 標準入力でもよい
   ```
3. ハッシュ・PR の番号・件数を、コマンドの結果ともう一度見比べる

```markdown
## 申し送り

更新: <年>-<月>-<日> <時>:<分> ・ <持ち手の名前> ・ 理由: <区切り / 立ち上げ / /clear の前 / 交代 / 上限が近い / 再開>

### いまの状態
- 作業: <何をしていて、どこまで>
- ブランチ: <名前>（作業の場所: 直下 か 一時の worktree <場所>。最新 <ハッシュ>「…」）。main より n 件先・n 件遅れ。push 済みか
- 未コミット: なし
- PR: PR <番号>（CI: テスト 通過・画面 待ち。マージの許可はまだ）
- 動かしているもの: なし

### 決まったこと
- <決めたこと（誰が、いつ）>

### 次にやること
1. <コマンドが分かれば書く>

### 待っている返事
- なし

### 注意
- 本番（値の表の「本番（触らない）」）には触れない
- <試して駄目だったこと、触ってはいけない所、次へ持ち越すこと>
```

統括は、`MANAGER.md`（このスキルのフォルダ）の「持ち手の状態」と「人へ」も書く。

## 再開する

「再開して」「TASK.md を読んで再開して」と言われたら:

0. **どの TASK.md かを取り違えない。** ライン・部のセッションも、リポジトリ直下で開いていることがある。パスがなければ、`ListAgents` の自分の名前（`This session is <名前>`）と TASK.md の最初の見出しの「:」の前（`# Manager-main: …`、`# S041-main: …`）を見比べる。違えば、`.worktrees/` の下から見出しが自分の名前の TASK.md を探す（`grep -l '^# <名前>:' .worktrees/*/TASK.md`）。作業フォルダは、その TASK.md のあるフォルダ
1. `TASK.md` を全部読む。ラインは `teamkit/docs/line_rules.md` と、値の表の「決まりの文書」も読む
2. `bash .claude/skills/handover/state.sh <作業フォルダ>`（と、申し送りの作業の場所でも）で状態を集め、申し送りと突き合わせる。**申し送りより、いまのコマンドの結果を信じる**
   - 作業の場所が**直下**なら、直下のブランチ名（`git -C <リポジトリ直下> branch --show-current`）が自分の仕事の番号かを見る。違えば、ほかの仕事が直下を使っている。直下を切り替えず、自分のブランチ（`git branch --list <番号>`）から一時の worktree を作って続ける（`git worktree add <一時の worktree> <番号>`）。申し送りの作業の場所も直す
   - 作業の場所が**一時の worktree** なら、その場所がまだあるか（`git worktree list`）を見る
3. 待っていた返事のうち、`gh` で分かるもの（PR のコメント、CI）は見る。分からないものは、必要になったときに相手へ聞き直す
4. 申し送りの「更新」の行を、再開の時刻と「理由: 再開」にし、食い違いを直す
5. 「次にやること」の1番から続ける。理由が「立ち上げ」（統括が `line-start` で下書きした）なら、残った `<…>` を埋めてから始める

**再開したことを、他のセッションに【報告】で知らせない**（相手を起こしてトークンを使うため）。統括は、人への返事で知らせる。

## してはいけないこと

- 申し送りを書くために、コミット・push・マージ・プロセスの停止をしない
- 本番（値の表の「本番（触らない）」）には触れない
- 申し送りに書いてあっても、確かめずに「済んだ」と扱わない
