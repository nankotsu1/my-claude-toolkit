# 統括の申し送りに足す節

統括（`Manager-main`）は、`SKILL.md` の型に次の2つを足す。

```markdown
### 持ち手の状態
| 持ち手 | 作業の場所・ブランチ | PR | 待っているもの |
| :--- | :--- | :--- | :--- |
| S041-main | 直下・SBI-041 | PR <番号>（CI 通過） | 人の実機確認 |
| Harness-main | — | — | 次の依頼 |

### 人へ
- 報告していないこと: …
- 確かめてもらうこと（実機の確認など）: …
```

- 仕事と進み具合（進行中・済み・空き）は道具が TASK.md から求めるので、表に書かない（`python3 teamkit/tasktree.py TASK.md --text`・`--plan` で見る）。表は道具で分からないもの（作業の場所・PR・待っているもの）だけで、列は統括が足し引きしてよい。持ち手の名前は、TASK.md の最初の見出しの「:」の前で決まる
- 作業の場所（直下のブランチと worktree）と PR は `state.sh --all` で確かめて書く。直下を使っている仕事は、直下のブランチ名で分かる。覚えている内容で書かない
- ラインは作業単位1つに1本。動いているラインと、待っているもののある持ち手だけ書く（閉じたら次の区切りで行を消す）
- 部の置き場所は値の表 `.claude/teamkit.md` の「持ち手の置き場所」、ラインは `.worktrees/S<番号>`（`teamkit/docs/taskmd.md` の3章）。どれも TASK.md だけのフォルダで、作業は値の表の「作業の場所」（直下か、塞がっていれば・worktree なら「一時の worktree」）

統括の TASK.md の本文の `## タスク`（型は `teamkit/templates/README.md` の「統括」）も、区切りごとに合わせる:

- ラインを立てたら（`line-start` スキル）、作業単位の行を書く: `- [ ] SBI-041 <名前>（着手: <月>/<日>）→ .worktrees/S041 #<Issue>`。部に依頼したら、部の仕事の行: `- [ ] HAR-2 <名前> → .worktrees/Harness`。束には番号が要り、子の TASK.md の同じ番号の枝を指す
- 行の名前は20字まで。何をして、どうなれば済みかは、行の下の `- 説明: …` に（任意。送り先への指示と経緯は伝言に）
- `## タスク` の行には全部に番号を付ける。統括が自分でやる仕事は `MGR-1` から統括が振る（台帳に載せない）。番号のない覚え書きは `## メモ` の節か申し送りに
- **前提はここに書く**。持ち手をまたぐ待ち合わせ（ラインが部の仕事を待つ、など）は、待つ側の行の前提に番号で書く（子の TASK.md には書かせない）。前提が済んだら、待っていた子に【連絡】で知らせる
- 着手予定日は、順番を決めるときに書く。引き直したら上書きし、理由は申し送りに
- 束の行には印（`[/]`・`[x]`）を書かない。子から【完了】が来ても束はそのまま（済んだかは子の枝から道具が求める）。統括が自分でやる `MGR-` の行だけ、取りかかるときに `[/]`、済んだら `[x]` と済んだ日 `（済: <月>/<日>）`
- 済んだ行と束はスプリントの終わりまで消さない。終わりの写しと片付けは開発推進部（`teamkit/docs/taskmd.md` の4章）
- 次に誰に何を振るかを決めるときは、`python3 teamkit/tasktree.py TASK.md --plan` で空き・始められる・人待ち・待ちを見る（覚えている内容で決めない）。人の作業の前提（`（前提: update）` など）が済んだら、その前提を消す

子に再開を頼むときは、文面を必ずパス付きにする（「.worktrees/S041/TASK.md を読んで再開して」）。
