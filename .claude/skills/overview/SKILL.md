# 全体像を答える（overview）

答え方は3つ。**「全体像を出して」と言われたら 1 の文字の全体像を、「計画を出して」「次に何を振れるか」なら 1b の計画と振る案を、「〜のタスクを見せて」（持ち手・期間・状態で絞る問い）なら 1c の絞った一覧を返す。** 前提を起こして TASK.md に書く（「計画を立てて」）は、別の `planning` スキル。

| | 答えるもの | 部品 | 読むもの |
| :--- | :--- | :--- | :--- |
| 1 文字の全体像 | 誰が何を受け持ち、どこまで済んだか | `teamkit/tasktree.py --text` | TASK.md と、束の先の子の TASK.md だけ |
| 1b 計画 | 空いている持ち手、始められる行、人待ち、待ち（何を待つか）。続けて振る案 | `teamkit/tasktree.py --plan` | 1 と同じ（ツリー全体） |
| 1c 絞った一覧 | 持ち手・期間・状態で絞った行の表 | `teamkit/tasktree.py --list` | 1 と同じ（ツリー全体） |

どれも、先に 0 で人を待っている持ち手を集めて部品に渡す。

## 0. 人を待っている持ち手を集める（ListAgents）

部品は TASK.md だけで全体像と計画を出す（進行中は `[/]` と枝から求め、セッションが動いているかでは決めない。`teamkit/docs/views.md`）。人を待っている持ち手を渡すと、その持ち手に任せた束が ✋（人待ち）になる。

1. `ListAgents` を呼ぶ。各行の先頭の名前（後ろの ` [ref]` は外す）がセッション名で、TASK.md の持ち手の名前と同じ文字
2. `--waiting`: 行が人の入力や許可を待っていると示しているもの。サブエージェントの行（セッションでないもの）は渡さない
3. 名前は「,」で区切って1つにまとめる:

```bash
python3 teamkit/tasktree.py TASK.md --plan --waiting S041-main
```

- 人を待っている持ち手がない、`ListAgents` が使えないときは、`--waiting` を付けずに動かす
- 一覧は呼んだ時点のもの。覚えている一覧を使い回さず、答えるたびに呼ぶ

## 1. 「全体像を出して」と言われたら（文字の全体像）

```bash
python3 teamkit/tasktree.py TASK.md --text --waiting <0 の名前>   # 統括（リポジトリ直下の TASK.md）
python3 teamkit/tasktree.py .worktrees/S041 --text                # 部・ラインの全体像（フォルダでも TASK.md でもよい）
```

- どの TASK.md かは、聞いたセッションと言葉で決める。統括と、とくに指定のないときはリポジトリ直下の `TASK.md`。部・ライン・部下が自分の分を聞かれたら、自分の TASK.md（再開文のパス）。「S041 の全体像」「Req の全体像」のように持ち手を名指しされたら、そのフォルダ
- 書き出し（Markdown の箇条書き）を、**手を加えずにそのまま**返す。見出しは持ち手の名前（TASK.md の最初の見出しの「:」の前）、束の行の下に子の TASK.md の行。🔄 は `[/]` の行と、枝に `[/]` か `[x]` があって全部は済んでいない束。日付（`（着手: 6/2）`・`（済: 6/3）`）は行の文面のまま。済んだ行は「済 n 件」に畳まれている。全部を見たいと言われたときだけ `--all`
- 前置きや要約は足さない
- 読むだけ。GitHub も読まないので、スマホのチャットからでも速い（`ListAgents` も読むだけ）
- ✋ は、0 で人を待っている持ち手を渡したときだけ出る
- `teamkit/tasktree.py` がないときは、TASK.md の `## タスク` の行を読んで同じ形で答え、部品がないことを1行添える

## 1b. 「計画を出して」「次に何を振れるか」と言われたら

```bash
python3 teamkit/tasktree.py TASK.md --plan --waiting <0 の名前>
```

- 空きは、束のフォルダの持ち手のうち、始められる仕事も 🔄 もないもの（求め方は `teamkit/docs/views.md`）
- どの TASK.md かは 1 と同じに決める。前提の番号はツリー全体（リポジトリ直下の TASK.md からたどれる行）で探すので、統括はリポジトリ直下の `TASK.md` を渡せばよい
- 書き出し（「# 計画 — …」に続く、空き・始められる・人待ち・待ちの行）を、**手を加えずにそのまま**返す。値のない項目は出ない
- 足してよいのは、次に当たったときの1行ずつだけ:
  - 「待ち: … ← SBI-099（見つからない）」: 前提の番号の書き間違いか、その行がまだどの TASK.md にもない。直すのはその行の TASK.md の持ち主（前提は親の TASK.md にだけ書く）
  - 子（部・ライン）の TASK.md の中の行に、ほかの持ち手の番号の前提がある: 前提を書くのは親の TASK.md だけなので、統括の行に移す
  - 「人待ち: … — 人の作業: update」: 人の作業が済んでいれば、その TASK.md の持ち主が前提を消すか `[x]` を付ける（部品には済んだか分からない）
- 部品は振り先を勧めず、時間の見通しやネックも出さない（事実と案を分けるため）。振る案は、書き出しのあとにこのセッションが出す（下の「振る案」）

### 振る案

書き出しのあとに「振る案」の見出しを付け、**始められる仕事を空いた持ち手に振る案**を、1行に1つ、理由を添えて出す。書き出しの行は直さず、案は書き出しと分けて書く（どこからが部品の事実で、どこからが案かが分かるように）。

```markdown
### 振る案（決めるのは統括）
- SBI-041 → 新しいライン S041-main: 前提の REQ-2 が済んだ。line-start で立てる
- REQ-3 → Req-main: 待ちの 2 行がこれを待っている
```

- 材料: `--plan` の空きと始められる、それぞれの行の TASK.md・台帳の節（触る所・依存の事実。台帳の場所は値の表 `.claude/teamkit.md` の「台帳」）・Issue。読む量を抑え、行を探して読む（`grep -n '<番号>'`）
- 考え方（理由に書く）: SBI（ラインの仕事）は新しいラインを立てる案に（ライン1本に作業単位1つ）、部の番号（`REQ-`・`HAR-`・`TST-`・`DEV-`）はその部に。同じ所を触る仕事は同時に走らせない（ぶつかりを避ける）、待たれている数（待ちの行の「← 番号」に出る回数）の多い仕事を先に。着手予定日（`（着手: …）`）が近いものを先に
- 空きがない、または始められるがないときは、「振る案: なし（空きがない）」の1行だけ
- 前提が書いていない行が多くて計画がうすいときは、`planning` スキルで前提を起こすことを1行で勧める
- 案は案のまま。振る伝言は送らず、TASK.md も書かない（決めるのは人と統括で、伝言は承認のあとに統括が送る）。目安（時間）は出さない
- `--plan` がない（古い `teamkit/tasktree.py`）ときは、そう伝えて 1 の全体像を返す

## 1c. 「〜のタスクを見せて」と言われたら（絞った一覧）

「今日のタスク」「ハーネス部の向こう3日のタスク」「S041 の止まっているもの」のような問いは、言葉を**日付と持ち手の名前に置き換えて**、部品の `--list` に渡す。部品は日付と名前だけを受け、言葉は読まない（どこで呼んでも同じ結果になるように。引数と既定は `teamkit/docs/views.md` の7章）。

```bash
python3 teamkit/tasktree.py TASK.md --list --who Harness --from 11/25 --to 11/27 --waiting <0 の名前>
```

- TASK.md は、聞いたのが部・ラインでも**リポジトリ直下の `TASK.md`**（ツリー全体）を渡し、持ち手は `--who` で絞る（自分の TASK.md を渡すと、ほかの持ち手の行が入らない）
- 今日の日付は、覚えている日付を使わず `date +%m/%d` で取る（n 日あとは `date -d '+2 day' +%m/%d`。GNU の date がなければ `python3 -c 'import datetime as d; print((d.date.today()+d.timedelta(2)).strftime("%m/%d"))'`）

置き換え（言葉にないものは渡さない。渡さない条件では絞らない）:

| 言葉 | 引数 |
| :--- | :--- |
| 「今日」 | `--from <今日> --to <今日>` |
| 「明日」 | `--from <明日> --to <明日>` |
| 「向こう n 日」「n 日以内」 | `--from <今日> --to <今日から n-1 日あと>`（向こう3日は今日・明日・あさって） |
| 「今週」 | `--from <今日> --to <その週の日曜>` |
| 「来週」 | `--from <次の月曜> --to <その次の日曜>` |
| 「11/25 から 11/30」 | `--from 11/25 --to 11/30`（年は書かなくてよい。年をまたいでもよい） |
| 部の名前（「ハーネス部」「要求分析部」「テスト部」「開発推進部」） | `--who <その部のセッション名>`（`teamkit/docs/roles.md` の「名前（セッション名）」の表。末尾の `-main` は省いてよい。例 `--who Harness`） |
| 「統括」 | `--who Manager` |
| ライン（「S041」「SBI-041 のライン」） | `--who S041` |
| 「自分の」 | `--who <このセッションの名前>`（`ListAgents` の `This session is <名前>`） |
| 「〜だけ」「本人の」（任せた先を入れない） | `--who-only` を足す |
| 「予定のもの」「予定に入っている」 | `--planned-only` を足す（着手予定日が期間の中の行だけ） |
| 「済んだ」 | `--state done` |
| 「進行中」「やっている」 | `--state doing` |
| 「始められる」「手を付けられる」 | `--state ready` |
| 「人待ち」「確認待ち」 | `--state human` |
| 「止まっている」「待っている」 | `--state human,blocked` |
| 「残り」「未済」「終わっていない」 | `--state open` |

- `[/]` で前提の残る行は進行中（`doing`）で、残る前提はブロッカーの列に出る。「止まっている」と聞かれたら、`--state human,blocked` の一覧に続けて、`--state doing` の行のうちブロッカーのあるものも添える
- 期間を渡すと、既定は期間に**掛かる**行（未着手は着手予定日が期間の中か、それより前なのに未着手。進行中は全部。済んだ行は済んだ日が期間の中）。日付のない未着手の行は入らないので、0 件なら「日付のない行は入らない」と1行添える
- 形（`--format`）: チャットには既定の `md`。表計算で開きたいと言われたら `--format csv -o <ファイル>`、ほかの道具に渡すなら `--format json`（項目は `no`・`name`・`desc`・`state`・`holder`・`path`・`start`・`finished`・`blockers`・`human`・`issues`）。書き出すファイルはスクラッチの場所に置き、パスを伝える
- 書き出し（表と、終わりの「n 件（…）」の行）は**手を加えずにそのまま**返す。前に1行だけ、置き換えを書く（「今日 = 11/25、ハーネス部 = Harness-main として」）
- ツリーにない持ち手の名前は、部品が標準エラーに出す。そのときは 1 の全体像の見出しの名前から近いものを聞き返す
- 説明（`desc`）は表に出ない。「中身も」と言われたら `--format json` の `desc` か、その行の TASK.md の説明の行を読んで添える
- `--list` がない（古い `teamkit/tasktree.py`）ときは、そう伝えて 1 の全体像を返す

## してはいけないこと

- ファイルを書かない（書き出しはそのまま返す）
- GitHub に書かない
- 本番（値の表の「本番（触らない）」）には触れない
