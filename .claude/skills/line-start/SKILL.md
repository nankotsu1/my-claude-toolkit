# ラインを立てる（line-start）

ラインは作業単位（SBI）1つに1本。統括が、前提の済んだ作業単位にラインを立て、ラインはマージして【完了】を送ったら閉じる（`teamkit/docs/line_rules.md` の1章）。作業単位の切り替えはない。このスキルは統括が、リポジトリ直下で使う。

台帳の場所・報告の写し先・ラインのポートの枠・決まりの文書・本番は、値の表 `.claude/teamkit.md` から読む（`draft.py` も同じ所を読む）。

## 1. 確かめる

```bash
python3 teamkit/tasktree.py TASK.md --plan       # その SBI が「始められる」にあること（前提が済んでいる）
git fetch origin
```

- 台帳（`python3 teamkit/values.py 台帳`）に、その番号の節（作るもの・確かめ方・触る所。形は `teamkit/docs/install.md` の「台帳の形」）が origin/main にあること。なければ要求分析部に作業計画を頼む
- ラインにするのは SBI の番号だけ（`SBI-041`、子の行を1本にするなら `SBI-041-1`）。部の仕事（`REQ-`・`HAR-`・`TST-`・`DEV-`）はラインにせず、部へ【依頼】で頼む
- 同じポートの枠（番号を値の表の「ラインのポートの枠の数」で割った余り）のラインが動いていれば、空いた枠を選ぶ

## 2. 置き場所と下書きを書く

ラインの置き場所 `.worktrees/S041` は TASK.md だけを置くフォルダで、git の worktree にしない（部と同じ形。`teamkit/docs/taskmd.md` の2章）。コードを直す場所は、ラインが進め方の 0 で用意する（値の表の「作業の場所」。既定は直下でブランチを切り、塞がっていれば・`worktree` なら一時の worktree。`teamkit/docs/line_rules.md` の2章）。統括は worktree もブランチも作らない。

```bash
python3 .claude/skills/line-start/draft.py SBI-041            # 書かずに見る（注意は標準エラー）
python3 .claude/skills/line-start/draft.py SBI-041 --write    # 置き場所 .worktrees/S041/ を作り、TASK.md を書く（無いときだけ）
```

- `--write` は、置き場所に空を指す `.git` ファイルも置く（そこで使った git が直下の main に当たらず止まるように）
- 子の行を1本のラインにするとき（`SBI-041-1`）も、フォルダとセッション名は親の番号（`S041`・`S041-main`）、ブランチは `SBI-041-1`
- 枠を変えるときは `--port-slot <枠>`

`draft.py` が埋めるもの（ひな形 `teamkit/templates/TASK.template.md` から）:

- 見出し `# S041-main: SBI-041 <名前>`
- `## タスク` の行: 台帳の子の行の表（`SBI-041-1 …`）があればそれ、なければ作るものの箇条書きに `SBI-041-<連番>` を振る。最後に「テスト・レビュー・PR」の行。名前は20字まで（長ければ縮め、注意に出す。見直す）、作るものと確かめ方の要点は行の下の `- 説明: …` に（全文は材料の節）
- 持ち場（台帳の触る所）、材料（作るもの・確かめ方の写し）、この作業単位の値（置き場所、ブランチ、作業の場所（値の表の作業の場所に合わせて、直下の空きの見方か一時の worktree）、ポートの枠、PR のタイトル、報告の写し先、実機確認）、並行して動いているもの（台帳の「ファイルが重なる所」）、申し送りの最初の形
- 値の表にない値は `<…>` のまま残り、注意に出る
- **前提と着手予定日は書かない**。ラインの TASK.md の行には、ほかの持ち手の番号を前提に書かない。持ち手をまたぐ待ち合わせは統括の TASK.md の行の前提で表し、前提が済んだら統括がラインに【連絡】で知らせる。中の行の着手予定日はラインが書く

## 3. 埋めて、統括の行を書く

- 注意の「まだ埋めていない」に出たものを埋める（Issue の本文、並行して動いているもの、実機確認が要るか）。行の名前が長すぎれば短く直してよい（番号は変えない）
- 統括の TASK.md に束の行を書く（あれば直す）: `- [ ] SBI-041 <名前>（着手: <月>/<日>）→ .worktrees/S041 #<Issue>`。前提はこの行に書く。束には印（`[/]`・`[x]`）を書かない（進み具合はラインの枝 `SBI-041-…` から道具が求める）

## 4. 立ち上げの指示文を出す

ラインのセッションは人が開く（セッション名を `S041-main` にしてもらう）。指示文は `<パス>/TASK.md を読んで…` で書き出す（どの TASK.md の持ち手かが、書き出しで人にも道具にも分かるように）:

```text
.worktrees/S041/TASK.md を読んで始めて
```

## 印と日付

ラインの中の行はラインが、取りかかるときに `[/]`、済んだら `[x]` と `（済: <月>/<日>）` を書く。統括の束の行には印を書かず、【完了】を受けても束はそのまま（`teamkit/templates/README.md`）。

## してはいけないこと

- 動いているラインの TASK.md を上書きしない（`--write` は TASK.md があると止まる。`--force` は前のラインを閉じたあとだけ）
- 台帳と仕様の文書は直さない。作業計画が足りなければ要求分析部に頼む
- 本番（値の表の「本番（触らない）」）には触れない
