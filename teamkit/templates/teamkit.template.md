# teamkit の値（<リポジトリの名前>）

導入したリポジトリだけの値。teamkit のスキルとスクリプトが読む（`teamkit/values.py`）。共通の決まりは `teamkit/docs/`、詳しい決まりは「決まりの文書」に書き、食い違うときは、この表と決まりの文書に従う。

書き方:

- 1列目が項目、2列目が値。項目の名前は変えない（スクリプトが名前で読む）。3列目からは説明で、道具は読まない
- 値はコードの書き方（`…`）で囲む。いくつもあるときは「、」で並べる。コードの外の文と、全角の括弧（…）の中は説明として読み飛ばされる（括弧の中にコードを書いても値にならない）
- 値の中の「|」は「\|」と書く（表の区切りと見分けるため）
- 文で書く項目（「コンテキストの目安の見え方」「申し送りの注意」）は、コードの書き方を使わずに文で書く
- 使わない項目は、値を「—」にする（スキルは、その値を使う所を飛ばす）
- 道具が読むのは、見出しの1列目が「項目」の表だけ。導入したリポジトリだけの一覧（持ち手と置き場所、ポートの割り当て など）は、見出しの違う表で同じファイルに足してよい
- 値の列は見本（架空の値）。そのリポジトリの値に書き換える

| 項目 | 値 | 読むもの・使う所 |
| :--- | :--- | :--- |
| 決まりの文書 | `docs/rules.md` | 導入したリポジトリの決まり（テストの流し方の詳しい所、実機確認の入れ方、大きな文書 など）。ライン・部がセッションの始めに、`teamkit/docs/line_rules.md` と一緒に読む |
| 台帳 | `docs/backlog.md` | 作業単位ごとの作業計画の一覧（形は `teamkit/docs/install.md` の「台帳の形」）。`line-start`・`planning` が読む |
| 報告の写し先 | `notes/reports/` | 報告の写し（`SBI-<番号>.md`）を置くフォルダ。`line-start` が下書きに書く |
| 持ち手の置き場所 | `.worktrees/Req`、`.worktrees/Harness`、`.worktrees/Test`、`.worktrees/Dev` | 統括のほかに常にいる持ち手（部）の TASK.md のフォルダ。TASK.md だけを置き、git の worktree にしない。ラインと部下の置き場所は番号で決まる（`teamkit/docs/taskmd.md` の3章）。`handover` が再開と統括の申し送りで使う |
| 作業の場所 | `直下` | コードや文書を直す場所の既定。`直下`（既定。リポジトリ直下でブランチを切る。人が開いている VS Code のまま diff とコミットが見える。一度に1つの仕事だけで、使っている仕事は直下のブランチ名で分かる）か `worktree`（仕事ごとに一時の worktree。直下をいつも既定のブランチに保ちたいリポジトリ。例: 直下から本番に入れる）。`line-start` が下書きに書き、`handover` が再開で使う（`teamkit/docs/line_rules.md` の2章の 0） |
| 一時の worktree | `.worktrees/wt/<番号>` | 作業の場所が `worktree` のときと、直下が塞がっているときに、仕事ごとに `origin/main` から作る worktree。`<番号>` は仕事の番号で、ブランチの名前と同じ。`line-start` が下書きに書く |
| 写しの置き場 | `.worktrees/snapshots/` | スプリントの終わりと目標を閉じるときに、TASK.md を木ごと写すフォルダ（git に入らない所。`teamkit/docs/taskmd.md` の4章）。中に区切りごとのフォルダを作る。`sprint-end` が読む |
| テスト（関係する所） | `python3 -m unittest tests.test_<名前>` | 作業の途中に流すテスト |
| テスト（全部） | `python3 -m unittest discover tests` | PR の前に1回流すテスト |
| 本番（触らない） | `8080`、`~/.myapp/` | 人だけが触る本番のポート・データの置き場所・設定のファイル。スキルは触らないことを書き、`state.sh` は数えない |
| 模擬サーバーのコマンド | `myapp.py` | 模擬環境で立てるサーバーのコマンドの名前（プロセスを探す語）。`state.sh` が「動かしているもの」に出す |
| 模擬環境のポートの範囲 | `20000〜20099` | テストと模擬環境に使うポート全部。`state.sh` が聞いているポートを出す |
| ラインのポートの始まり | `20010` | ラインの模擬環境のポートの枠の、いちばん小さい番号。`line-start` が下書きに書く |
| ラインのポートの枠の数 | `8` | 枠は作業単位の番号を、この数で割った余りで決まる |
| ラインのポートの枠の幅 | `10` | 1つの枠のポートの数 |
| コンテキストの目安の見え方 | 約15万トークン（ステータス行の表示などで見る） | `handover` が、区切りで `/clear` するかを決めるときの目安 |
| 申し送りの注意 | — | 申し送りを書くときに、導入したリポジトリで守ること（道具が読み違える書き方など） |
| 実機確認の基準 | `docs/verify.md` | 実機確認が要るかの基準と手順（型は `teamkit/docs/verify.md`） |
| レビューの観点 | `docs/review.md` | セルフレビューで当てる観点の一覧 |
