# 報告のひな形

## 【完了】（ライン・部・部下 → 親）

1行目に種別と要点（受け手の一覧に見出しとして出る）、最後に2行。中身がなければ「なし」。2行は省かない（「なし」の報告で、前の判断待ちが外れる）。

```text
【完了】SBI-<番号> をマージしました
- PR <番号>、マージ <ハッシュ>
- <決めたこと・持ち越し。なければ書かない>
人が判断すること: なし
止まっている: なし
```

- 「人が判断すること:」: 仕事を終えたあと、**人に**残す事柄（実機確認、`update` の実行、次に選んでほしいこと）
- 「止まっている:」: 親に答えてほしくて先へ進めない事柄
- 行頭は欄の名前ちょうど（前に「- 」や空白を付けない。コロンは半角）。あれば同じ行に続けるか、次の行から「- 」の箇条書き（次の空行か見出しまで）
- 実機確認が要る PR は、マージの前に「【報告】SBI-<番号> の PR <番号> を出しました」で送り、「人が判断すること: 実機確認（手順は PR）」と書く（`teamkit/docs/line_rules.md` の実機確認）

## 報告の写し（`SBI-<番号>.md`）

TASK.md の末尾の報告の節をマージの前に埋め、TASK.md ごと写し先へ写して PR に入れる。報告の節の中身:

```markdown
## 報告

- 変更点: <何をどう変えたか>
- 確かめた方法と結果: <テストの件数、CI、画像、実機確認>
- 決めたこと: <人と決めたこと、自分で決めたことと理由>
- 未解決の点: <残したこと、次へ持ち越すこと>
- 実機確認で見てほしい点: <要らなければ「なし（文書だけ／コマンドで確かめた）」>
```
