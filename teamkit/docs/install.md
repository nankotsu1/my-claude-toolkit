# teamkit の導入

teamkit（全体像の部品、進め方の共通部分、スキル5つ）を、リポジトリに導入する手順。部品は標準ライブラリだけの1ファイルで、TASK.md の型（`taskmd.md`）の語だけを読む。導入したリポジトリだけの値は値の表 `.claude/teamkit.md` に書くので、teamkit の中のファイルは直さずに使える。

必要なもの: Python 3.9 以上、git、Claude Code。`gh`（GitHub の CLI）はスキルの一部（PR の状態を見る所）が使い、なくても残りは動く。

## 1. 入れる

配布元（`teamkit/` と `.claude/skills/` のスキル5つがあるリポジトリ）から、導入するリポジトリの直下の同じ場所へ写す:

- `teamkit/` のフォルダごと（部品 `tasktree.py`、値の表を読む部品 `values.py`、型と決まり `docs/`、ひな形 `templates/`、部品とスキルのテスト `tests/`）
- スキル5つ: `.claude/skills/overview/`・`planning/`・`handover/`・`line-start/`・`sprint-end/`
  - スキルは Claude Code が `.claude/skills/` から読むので、`teamkit/` の中には置かない
  - シンボリックリンクにせず、ファイルを写す（Windows の git では、リンクが壊れやすいため）
  - 配布元の `.claude/skills/` にほかのスキルがあれば、それは写さない

写すコマンドの例（`<配布元>` と `<導入先>` は、それぞれのリポジトリの直下）:

```bash
cp -r <配布元>/teamkit <導入先>/
mkdir -p <導入先>/.claude/skills
for s in overview planning handover line-start sprint-end; do
  cp -r <配布元>/.claude/skills/$s <導入先>/.claude/skills/
done
```

配布元でテストを流したあとなら、写した先の `__pycache__/` は消してよい（git には入れない。3章の 1）。

## 2. 値の表を書く

ひな形 `teamkit/templates/teamkit.template.md` を `.claude/teamkit.md` の名前で入れ、そのリポジトリの値を書く。項目の名前は変えない（スクリプトが名前で読む）。使わない項目は「—」にする。

| 項目 | 書くもの |
| :--- | :--- |
| 決まりの文書 | そのリポジトリの決まりの文書（共通の決まりとの差、テストの詳しい流し方、実機確認の入れ方）。なければ「—」 |
| 台帳 | 作業単位ごとの作業計画の一覧のファイル（形は下の「台帳の形」） |
| 報告の写し先 | 報告の写し（`SBI-<番号>.md`）を置くフォルダ |
| 持ち手の置き場所 | 部の TASK.md を置くフォルダ（TASK.md だけを置き、git の worktree にしない） |
| 作業の場所 | コードや文書を直す場所の既定。`直下`（既定。リポジトリ直下でブランチを切る。人が開いている VS Code のまま diff とコミットが見える）か `worktree`（仕事ごとに一時の worktree。直下をいつも既定のブランチに保ちたいリポジトリ。例: 直下から本番に入れる） |
| 一時の worktree | worktree を作る場所（`<番号>` を仕事の番号に置き換える）。作業の場所が `worktree` のときと、直下が塞がっているときに使う |
| 写しの置き場 | スプリントの終わりと目標を閉じるときに TASK.md を木ごと写すフォルダ（git に入らない所）。`sprint-end` が使う |
| テスト（関係する所）・テスト（全部） | テストのコマンド |
| 本番（触らない） | 人だけが触る本番のポート・データの置き場所・設定のファイル |
| 模擬サーバーのコマンド・模擬環境のポートの範囲 | 模擬環境で立てるサーバーと、テストに使うポート。`handover` の状態の集め方が使う |
| ラインのポートの始まり・枠の数・枠の幅 | ラインごとに分ける模擬環境のポート。枠は作業単位の番号を枠の数で割った余り |
| コンテキストの目安の見え方 | 区切りで `/clear` するかを決める目安と、それがどこで見えるか |
| 申し送りの注意 | 申し送りを書くときに、そのリポジトリで守ること。なければ「—」 |
| 実機確認の基準 | 実機確認が要るかの基準と手順の文書（型は `verify.md`） |
| レビューの観点 | セルフレビューで当てる観点の一覧の文書 |

道具が読むのは、見出しの1列目が「項目」の表だけ。そのリポジトリだけの一覧（持ち手と置き場所、ポートの割り当て など）は、見出しの違う表で同じファイルに足してよい（数字とパスを1か所にまとめられる）。

書けたら、`python3 teamkit/values.py` で読めることを確かめる（項目ごとに値が1行ずつ出る）。

## 3. 当てはめる

1. `.gitignore` に `/TASK.md`・`/.worktrees/`・`__pycache__/` を足す（TASK.md は git に入れない。部とラインの TASK.md は `.worktrees/` の下にある。`__pycache__/` はスキルが部品を読むとできる。どれも、直下が空いているかの見方（`git status --porcelain`。`line_rules.md` の2章の 0）が変更と数えないように）
2. `CLAUDE.md` に、型（`teamkit/templates/`）、決まり（`teamkit/docs/line_rules.md` と値の表）、スキル5つの名前を書く
3. 台帳のファイルを作る（形は下）。作業単位の番号は `SBI-001` から
4. 統括の TASK.md をリポジトリ直下に、ひな形 `teamkit/templates/TASK.template.md` を `TASK.md` の名前で入れて書く（`# Manager-main: <目標>`、`## タスク`、子に任せた行は `→ <子のフォルダ>`）

## 4. 台帳の形

`line-start` スキル（`draft.py`）は、台帳から作業単位の節を読んで、ラインの TASK.md の下書きを作る。読むのは次の形:

```markdown
| 番号 | 名前 | 持ち手 | 依存の事実 |
| :--- | :--- | :--- | :--- |
| SBI-041 | ログイン機能 | ライン S041-main | — |

### SBI-041 ログイン機能

- 作るもの:
  - ログイン画面: メールとパスワードで入れる画面
  - パスワードの再設定: 再設定のメールを送る
- 確かめ方: テストが通る。実機確認（人が入れて見る）
- 触る所: `src/auth.py`、`tests/test_login.py`

ファイルが重なる所: SBI-041 と SBI-042 は認証の部品で重なる。
```

- 節の見出しは `## <番号> <名前>` か `### <番号> <名前>`。節は、同じか浅い見出しの手前まで
- 「- 作るもの:」「- 確かめ方:」「- 触る所:」を読む。作るものの入れ子の箇条書きは、1つずつ `SBI-041-<連番>` の行になる。名前の直後の括弧の注記（「- 作るもの（基準は …）:」）も読む
- 子の行を表で書くとき（`| SBI-041-1 | <名前> |`）は、表の行がそのまま `## タスク` の行になる
- 「ファイルが重なる所:」で始まる行の文のうち、その番号に触れるものが、下書きの「並行して動いているもの」に入る
- 節の中に「実機確認」の語があれば、実機確認ありと書く

## 5. 確かめる

- `python3 teamkit/tasktree.py TASK.md --text`（全体像）と `--plan`（計画）
- そのあと Claude Code に「全体像を出して」「計画を出して」と言い、同じ書き出しが返ること
- `python3 -m unittest discover teamkit/tests`（部品とスキルのテスト。スキルのテストは、入れたスキル `.claude/skills/` と値の表を読む。値の表に台帳がないうちは、台帳を読むテストを飛ばす）

## 6. 気をつけること

- 束のフォルダはリポジトリ直下からの相対で読む（worktree の中からでも、もとのリポジトリの直下）。git のリポジトリの外では、TASK.md のあるフォルダから数える
- 入れ直すときは、`.gitignore` に `__pycache__/` があるかも確かめる（なければ、直下がいつも塞がって見える。3章の 1）
- 新しい版を入れるときは、`teamkit/` とスキル5つを入れ直す（いったん消してから写すと、配布元で消えたファイルが残らない）。値の表 `.claude/teamkit.md` は `teamkit/` の外にあるので上書きされない。配布の版の番号は持たない（部品の `VERSION` は TASK.md の読み方の版で、読み方を変えたときだけ上がる）
- teamkit の中のファイルを、そのリポジトリに合わせて直さない（入れ直すと消える）。値は値の表に、そのリポジトリだけの決まりは決まりの文書に書く
