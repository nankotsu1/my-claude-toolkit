# 全体像の見え方

全体像の部品 `teamkit/tasktree.py` が TASK.md から何を出すかの正。TASK.md の書き方（型）は `taskmd.md`、語の意味は `roles.md` の用語にある。部品を組み込むほかの道具（画面など）も、この見え方に合わせる。

## 1. 出すもの

部品は TASK.md を読むだけで、書き換えない。GitHub も読まない。標準ライブラリだけで動き、外へは何も送らない。

| 出すもの | 呼び方 | 中身 |
| :--- | :--- | :--- |
| 文字の全体像 | `python3 teamkit/tasktree.py <TASK.md かフォルダ> --text`（既定） | ツリー（行・束・進み・状態）を Markdown の箇条書きで（5章） |
| 文字の計画 | `… --plan` | 空き・始められる・人待ち・待ち（5章） |
| 図 | `… --html`（`-o` で書き出し先） | 持ち手ごとの帯の図と、図の下の一覧を、1枚の HTML で（6章） |
| 絞った一覧 | `… --list`（`--format` で形、`-o` で書き出し先） | 持ち手・期間・状態で絞った行の一覧を、Markdown の表・JSON・CSV・HTML のどれかで（7章） |

- 読むのは、渡した TASK.md（フォルダなら、その直下の TASK.md）と、束をたどった子と孫の TASK.md（3段まで）。束の相対のパスは、ツリーの根（ふだんはリポジトリ直下）から数える
- どれも同じ読み方で求める（文字の全体像・計画・図・絞った一覧で状態や数え方が食い違わない）
- 呼び出す側が渡せるもの（どれも任意。渡さなくても、全部の出すものが TASK.md だけで出る）:
  - **人を待っている持ち手**: その持ち手（か、その持ち手が任せた先）が、人の確認や判断を待っている。持ち手の名前で渡す（CLI は `--waiting`。くり返すか「,」「、」で区切る。関数は `holders`（持ち手の名前 → `"waiting"`、またはそれに待っているものの説明を足したもの。ほかの値は使わない））。セッションが動いているかどうかは渡さない（状態はそれで決めない）
  - **Issue のリンクの頭**: Issue の番号の前に付けると Issue のページになる URL（例 `https://github.com/<持ち主>/<リポジトリ>/issues/`。CLI は `--issue-url`）。渡さなければ、部品がツリーの根の git の設定の `origin` から求める（GitHub の形のときだけ。ネットにはつながない）。どちらもなければ、Issue は文字のまま
  - **写しの根**: スプリントの写し（`taskmd.md` の4章）のフォルダを渡すと（CLI は `--root`。写しの中の TASK.md を渡せば、渡さなくても部品が見分ける）、そのフォルダをツリーの根として、束の相対のパスと番号を、写しの中で数える。そのスプリントの終わりの全体像・計画・図が、今と同じ見え方で出る

## 2. 状態

行（束を含む）ごとに、次の5つのどれかを求める。手で書くのは、自分でやる行の `[/]` と `[x]` だけ。束の状態と、未着手の行の状態は、枝と前提から求める。

| 状態 | 文字 | 図と一覧のアイコン | 求め方 |
| :--- | :--- | :--- | :--- |
| 済み | ✅ | 緑の丸に白のチェック | `[x]` の行。束は、枝に行があって全部 `[x]` |
| 進行中 | 🔄 | 青の丸に白の ▶ | 下の「進行中」 |
| 始められる | ⬜ | 地の色の丸に青の輪 | 未着手で、待つものがない |
| 人待ち | ✋ | 橙の丸に白の人の形 | 前提に人の作業が残る。または、人を待っている持ち手に任せた束 |
| 着手不可 | ⏳ | 灰色の丸に白の砂時計 | 前提に書いた番号の行か、順番の1つ前の行が、まだ済んでいない |

- アイコンは形でも見分けられる（色を見分けにくい人にも分かる）。明るい画面でも暗い画面でも5つが見分けられること。行の字を薄くするのは着手不可だけ
- 未着手（`[ ]` の行と、枝に印のない束）は、上から順に当てはめる: 着手不可 → 人待ち → 始められる（人の作業とほかの番号の両方が残れば、着手不可）

### 束の枝

- 束の**枝**は、束の子の TASK.md の行のうち、番号が束と同じか、束の番号に `-` で続く行（束 `REQ-4` なら `REQ-4`・`REQ-4-1`・`REQ-4-2-1`）。子の TASK.md のほかの行は、この束に入らない
- 同じフォルダを指す束が2つ以上あっても、それぞれが自分の枝だけを持つ（子の行は、どれか1つの束にしか入らない）
- 枝の行が束（孫に任せた行）なら、その束も同じ決め方で孫の TASK.md の枝を持つ

### 前提の読み方

- 待ちになるのは、**書いた前提**（`（前提: …）`）と、**順番**（同じ TASK.md で自分でやる行の、1つ前の未済の行）。任せた行（束）は順番に入らず、書いた前提だけで待つ
- 番号は、**ツリー全体**で探す（ツリーの根の TASK.md から束をたどって読める行の全部。根に TASK.md がなければ、渡した TASK.md のツリー）。行の先頭の番号と、行の最後の Issue の番号（`#146`）の、どちらでも引ける。同じ番号が2つあれば、先頭の番号を先に、たどった順で最初のもの
- ツリーに見つからない番号は着手不可にし、「見つからない」と出す（書き間違いに気づけるように）
- 番号の形（`taskmd.md` の2章）でない語は**人の作業**。済んだかは道具に分からないので、持ち主が前提を消すか `[x]` を付けるまで残る
- 前提が循環していたら、その行は着手不可のままにし、図では循環を知らせる（6章）
- 始められるになりうるのは、持ち手ごとに、自分でやる行のうち最初の未済の行だけ（後ろの行は順番で着手不可）

### 進行中

- **行**: `[/]` の行。前提が残っていても 🔄 にし（担当が着手した事実を出す）、残る前提はブロッカーに出す
- **束**: 枝に `[/]` か `[x]` の行があり、全部は `[x]` でない。人を待っている持ち手に任せた束は、枝に印があっても人待ち
- セッションが動いているかでは決めない（止まっているセッションの仕事も、印のとおりに出す。止まっていることは図に出さない）

### 番号のない行

- `## タスク` の番号のない行は数えない。計画と図には出さず、文字の全体像の終わりに「番号のない行 n 件（数えない）」の1行だけを出す（書き忘れに気づけるように）。番号のない束も同じで、子は開かない

## 3. 数える単位と空き

計画（空き・始められる・人待ち・待ち）に数えるのは、ほかの持ち手に振れる単位（各 TASK.md の `## タスク` の行）。持ち手（束のフォルダ）ごとに次のように決める。

- **済んだ束**（枝の行が全部 `[x]`）は数えない。前提がその行を引いたら、済みとして扱う。図と文字の全体像では、済んだ束も開いて枝を見られる（スプリントの終わりまで、枝の行は子の TASK.md に残る）
- **済んでいない束**は、上から当てはめる
  1. 束の行に書いた前提で着手不可か人待ちなら、束の行を1つの仕事として数える。枝の未着手の行も同じ状態にし、計画には束の1行だけを出す
  2. 枝に行があれば、枝の行を数え、束の行は数えない（二重に数えない）
  3. 枝に行がない（子の TASK.md がない、子がまだ枝の行を書いていない、3段より深い）なら、束の行を1つの仕事として数える。この仕事の持ち手は子（束のフォルダ）
- 人を待っている持ち手による束の人待ちは、束を人待ちに出したうえで、枝の行もそのまま数える（上の 1 の「枝も同じ状態にする」は、束の行に書いた前提によるときだけ）
- **空き**: 束の持ち手のうち、数えた仕事に 🔄 も始められるもないもの（済んでいない束がない、残りが全部着手不可か人待ち）。枝に行がない束は、束の行が始められるなら空きにしない（もう振ってある）。セッションが動いているかでは決めない。図の帯の「空き」と文字の計画は、この1つの決め方で求める

## 4. 持ち手の名前と番号の短い形

- **持ち手の名前**: TASK.md の最初の見出しの「:」の前（`# Req-main: …` → `Req-main`）。見出しがないか「:」がないときは、TASK.md のあるフォルダの名前。長ければ約20字で切る。図の帯の名前は、末尾の `-main` を省いたもの
- **番号の短い形**（図の丸の下と一覧）: 頭の語の1文字目と残り（`SBI-041-2` → `S041-2`、`REQ-2` → `R2`、`MGR-1` → `M1`、`I-3-1` → `I3-1`）。数える行には全部番号があるので、ほかの付け方は持たない。全文はツールチップ

## 5. 文字の全体像と計画

文字では色と濃さが使えないので、状態は2章の文字（✅・🔄・⬜・✋・⏳）で書く。

**文字の全体像**（`--text`）: 1行目は TASK.md の見出し。続いて行ごとに、状態・文面・進み・Issue。束は、子の TASK.md のパスと、枝の行を字下げして3段まで。済んだ行は「✅ 済 n 件」の1行にまとめる（`--all` で全部）。進みは束の枝の「済んだ数/全体」。子の TASK.md がないか、枝の行がなければ「タスク一覧はありません」。番号のない行があれば、終わりに「番号のない行 n 件（数えない）」。行の説明（`taskmd.md` の2章）は、文字の全体像にも計画にも出さない（ツリーを短く保つ。説明は図の下の一覧で名前を押したときに出す）。

```text
# Manager-main: 会員機能を作る
- ✅ 済 1 件
- 🔄 REQ-4 通知メールの要求 0/2
  - （.worktrees/Req/TASK.md）
  - 🔄 REQ-4-1 通知の文面を詰める
  - ⬜ REQ-4-2 メール配信サービスを比べる（大きいので部下に任せる）
    - （.worktrees/REQ-4-2/TASK.md）
    - タスク一覧はありません
- 🔄 SBI-041 ログイン機能（前提: REQ-3） 1/3
  - （.worktrees/S041/TASK.md）
  - ✅ 済 1 件
  - 🔄 SBI-041-2 ログイン画面を作る
  - ⏳ SBI-041-3 パスワードの再設定
- ⏳ MGR-1 公開の時機を決める（前提: SBI-041, 人の返事）
```

**文字の計画**（`--plan`）: 1行目は「# 計画 — <TASK.md の見出し>」。続いて、空き・始められる・人待ち・待ちを、この順に1項目ずつ（値のないものは出さない）。始められる行には持ち手、人待ちには人の作業か待っている持ち手、待ちの行には「← 待つ行（持ち手と状態）」を添える（計画はセッションが読んで振る案を作るので、図の下の一覧より詳しく書く）。

```text
# 計画 — 会員機能を作る
- 始められる: REQ-4-2 メール配信サービスを比べる（大きいので部下に任せる）（REQ-4-2）
- 待ち: SBI-041-3 パスワードの再設定（S041-main） ← SBI-041-2（S041-main 🔄）
- 待ち: MGR-1 公開の時機を決める（Manager-main） ← SBI-041（S041-main 🔄）
```

## 6. 図

渡した TASK.md の1段と、その束の枝の1段を、持ち手ごとの横の帯に並べた図。枝の中の束（孫に任せた行）を押すと、その束の枝（孫の TASK.md の中の、同じ番号の行）の図に入り、図の上のたどった道を押すと戻る。

- **帯**: 持ち手ごとに横の帯を1本。いちばん上は、渡した TASK.md 自身の帯（束でない行）。その下に、束のフォルダごとに1本（TASK.md の順。同じフォルダを指す束は同じ帯に、それぞれの枝を子の TASK.md の順で並べる）。帯の左に持ち手の名前（4章）。空いている持ち手（3章の空き）の帯には、右に「空き」
- **丸**: 仕事1つを、状態のアイコン1つと、その下の番号の短い形だけで出す。名前・ブロッカーは図の下の一覧に出す。束の枝に行があれば、その行を1つずつ丸にする。なければ、束の行そのものを1つの丸にする。済んだ仕事も全部、帯の左から TASK.md の順に残し、そのあとに今と未着手の丸が続く（済んだ所から今までの流れが見える）。済んだ束も、枝の行を丸にする
- **押せる丸**: 押すと何かが起きる丸（枝の中の束は、その枝の図に入る。人待ちの丸は、呼び出す側が受け取るときに、待っているものを返す。下の「呼び出す側へ」）は、丸の外に点線の輪を付ける（リンクの色）。図の下の一覧のその行は、タイトルの後ろに「›」を付け、「›」を押したときだけ図に入る（返す）。名前を押したときは、下の「説明」のとおり。押しても何も起きない丸と行には付けない
- **並べ方**: 左から右へ。丸の列は「同じ帯のすぐ前の丸の列と、待つ丸（前提）の列のうち、いちばん右の列の次」。持ち手が自分でやる行どうしは、矢じりのない細い線で TASK.md の順に結ぶ（順番の線。2章の順番の待ち）。ほかの持ち手に任せた行（部下への束など）は並行して進むので線につながず、列は前提だけで決め（前提がなければ、その帯の済んだ丸の次の列）、ほかの丸と同じ列になったら縦にずらす（枝分かれに見える）
- **矢印**: 書いた前提だけを、待つ丸から待っている丸へ引く（帯をまたぐときは曲がった線）。ふだんは薄く細くし、丸か一覧の行に触れる（キーボードで選ぶ）と、その丸の前後の矢印だけを濃くする（全部を同じ濃さで描くと、帯をまたいで交差して込み合う）。順番の線とは、矢じりと色で見分けられる。待つ行が図の中にないときは、いちばん上に「ほかの所」の帯を足し、点線の丸で出す。見つからない番号は点線の丸に「？」。前提が循環していたら、その矢印を点線のエラーの色で出し、図の上に「前提が循環しています」と出す
- **大きさ**: 丸と丸の間は、隣の番号が重ならない所まで詰める（丸の中心の間は約34px、帯の高さは約46px、番号は小さめの等幅の字）。図を幅いっぱいに引き伸ばさない。帯の名前の欄は持ち手の名前が入る幅（約8〜9字）。収まらないときは横にスクロールし、開いたときは右端（今の所）に合わせる
- **ツールチップ**: 画面に出ていない情報だけを出す。丸は番号・名前・状態。着手不可は「待ち: <待つ行の番号>（<持ち手> <状態>）」、見つからない番号は「（見つからない）」。人待ちは「人の作業: <語>」か、呼び出す側が添えた待っているものの説明。切れていない文面と、アイコンと同じことは出さない
- **図の下の一覧**: 1列の表で、列は「状態｜着手｜済｜番号｜タイトル｜ブロッカー｜Issue」
  - 状態はアイコン、着手と済は行の日付を `11/24` の形で、番号は短い形（全文はツールチップ）
  - タイトルは、文面から日付・前提・束・Issue を外した名前。列の幅は中身に合わせ、長いものは約40字で折り返す（潰れないよう最小の幅も取る）。表の余りは右の端に回し、ブロッカーと Issue をタイトルの近くに置く。狭い画面では、ブロッカーと Issue を名前の下の2行目に回す
  - ブロッカーは、まだ済んでいない待つものの**番号の短い形だけ**（「,」で区切る。順番の待ちは1つ前の行の番号）。見つからない番号は短い形のあとに「?」。人待ちは人の作業の語か、呼び出す側が添えた待っているものの説明。待つ相手の持ち手と状態、束の進みは出さない（相手はツールチップと、その番号の行で分かる）
  - Issue は `#番号`。Issue のリンクの頭（1章）があれば、押すと Issue のページを新しいタブで開くリンクにする
  - 持ち手の列は作らない（番号の頭が持ち手を表す）
  - 並びは、状態によらず着手日の順の1つの表で、済んだ行も混ぜる（予定に対して前倒し・遅れが並んで見える）。着手日の同じ行と日付のない行は、帯と TASK.md の順。日付のない行は日付のある行のあと
  - 丸か一覧の行にマウスを乗せる（キーボードで選ぶ）と、もう片方の背景が光る
  - **説明**: 説明のある行は、名前に薄い点線の下線を付け（指のカーソル）、名前を押すと、その行の下に説明が開き、もう一度押すと閉じる（開いた行はこの画面の間だけ覚える）。説明のない行の名前は押せない。図の丸とツールチップには説明を出さない
- **呼び出す側へ**: 人待ちの丸と、一覧のその行の「›」を押したときは、呼び出す側が添えた待っているもの（`holders` の値に足した項目）を、呼び出す側の関数に返す（部品はその中身を知らない）

### 表示の設定

前の見せ方に戻せるよう、部品は次の切り替えを持つ（既定はこの文書の見せ方）。

| 設定 | 切り替えるもの |
| :--- | :--- |
| 済んだ丸をまとめる | 図で、済んだ仕事を帯の左の「済 n」にまとめ、押すと開く |
| 一覧の済んだ行を畳む | 図の下の一覧で、済んだ行をいちばん下の「▸ 済 n 件」に畳む |
| 一覧の上に空きを出す | 図の下の一覧のいちばん上に「空き: …」の1行を出す（帯の「空き」だけでは足りないとき） |
| ブロッカーに相手を添える | 一覧のブロッカーの番号に、待つ相手の持ち手と状態を括弧で添える |
| 帯の名前を持ち手の名前にする | 偽なら、帯の名前を束の行の文面にする |
| 丸をアイコンで描く | 偽なら、丸の代わりに名前を入れた箱で描く |
| 押せる丸の印 | 丸の外の点線の輪を、右上の小さな丸の印・細い実線の輪・印なしのどれかに変える |

## 7. 絞り込み

ツリーの行を、持ち手・期間・状態で絞り、1つの一覧で出す。「今日のタスク」「ハーネス部の向こう3日のタスク」のような問いに答えるため。文字の全体像・計画・図は絞らない（ツリーと図の形を崩さない）。

**一覧に入る行**: ツリー全体（束を3段までたどる）の、自分でやる行と、枝に行のない束の行（3章と同じく二重に数えない。枝のある束の行は出さず、枝の行で出る）。済んだ行も入る。

**絞り方**（どれも任意。渡さなければ、その条件では絞らない。複数を渡せば全部に当たる行）:

| 条件 | 決め方 | CLI |
| :--- | :--- | :--- |
| 持ち手 | 持ち手の名前（4章。末尾の `-main` は省いてもよい）を1つ以上。既定では、その持ち手が任せた先（束をたどった子孫）の行も入れる。切り替えで、その持ち手の TASK.md の行だけにする | `--who <持ち手>`（くり返すか「,」で区切る）、`--who-only` |
| 期間 | 始まりと終わりの日（同じ日なら1日）。既定では、期間に**掛かる**行: 未着手は、着手予定日が期間の中か、期間の終わりより前なのにまだ未着手（遅れ）。進行中は全部。済んだ行は、済んだ日が期間の中。切り替えで、着手予定日が期間の中の行だけ（状態によらない）にする。どちらでも、日付のない未着手の行と、済んだ日のない済んだ行は入らない | `--from <日>`・`--to <日>`（`11/25` か `2026-11-25`。年がなければ今日に近い年）、`--planned-only` |
| 状態 | 2章の5つ（済み・進行中・始められる・人待ち・着手不可）と「未済」（済み以外）から1つ以上 | `--state <状態>`（`done`・`doing`・`ready`・`human`・`blocked`・`open`。くり返すか「,」で区切る） |

**出す形**（`--format`。既定は `md`）:

- **`md` 文字の一覧**: Markdown の表。列は「状態｜着手｜済｜番号｜名前｜ブロッカー｜Issue」（6章の図の下の一覧と同じ。状態は2章の文字、番号は全文）。並びは着手日の順（6章と同じ）。終わりに「n 件」と、絞り込みの条件を1行
- **`json`**: 1件1行の配列。項目は、番号・名前・説明・状態・持ち手・TASK.md のパス・着手（`YYYY-MM-DD`）・済・ブロッカー（番号の全文の並び）・人の作業・Issue の番号。ほかの道具が読むので、項目の名前は英字にする
- **`csv`**: 表計算でそのまま開ける形（UTF-8、BOM 付き、1行目は列の名前）。列は `md` と同じに、持ち手を足す
- **`html`**: 6章の図の下の一覧と同じ見た目の表だけの1枚（説明は名前を押すと開く）。帯と丸は描かない

```text
| 状態 | 着手 | 済 | 番号 | 名前 | ブロッカー | Issue |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 🔄 | 11/24 |  | SBI-041-2 | ログイン画面を作る |  |  |
| ⏳ | 11/25 |  | SBI-041-3 | パスワードの再設定 | SBI-041-2 |  |

2 件（持ち手: S041-main と任せた先、期間: 11/25〜11/27 に掛かる行）
```

**言葉からの置き換え**: 「今日」「向こう3日」「ハーネス部」のような言葉を、日付と持ち手の名前に置き換えて呼ぶのは、スキル（`overview`）。部品は日付と名前だけを受ける（どこでも同じ結果になるように）。

## 8. しないこと

- いちばん長い道（ネック）と時間の見通しは出さない（TASK.md に目安を書かない）
- 振り先は勧めない（決めるのは統括。振る案は、スキルを使うセッションが出す）
- 前倒し・遅れの判定と印は出さない（人が日付を見て把握する）
- 指示を送らない。TASK.md を書き換えない
